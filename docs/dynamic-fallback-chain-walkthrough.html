Dynamic Fallback Chain Walkthrough

Date: 2026-04-15 Commit: 4d181ca Status: Deployed

The Problem It Solves

Before: Static fallback chains in proxy_server_config.yaml. When chutes_router dynamically discovered a new model (like Chimera-TEE), that model had no fallback chain → 429s reached the client.
After: The entire fallback chain is built dynamically from real-time Chutes utilization data. Every model gets a full 8-model chain, sorted best-to-worst.

How Each Component Works

1 chutes_router.py — Build the Chain

_get_utilization() — Fetches utilization data, cached 5 minutes:

# Cache check
if _utilization_cache is not None and now - _cache_timestamp < 300:
    return _utilization_cache

# Fetch fresh: GET https://api.chutes.ai/chutes/utilization
raw = await _fetch_utilization()

_score_model() — Lower score = better:

def _score_model(stats: dict) -> float:
    util = stats.get("utilization_current", 1.0)
    rate_limit = stats.get("rate_limit_ratio_5m", 0.0)

    if rate_limit > 0.25:  return 100.0  # Avoid rate-limited
    if util > 0.95:        return 90.0   # Avoid saturated
    if util < 0.01:        return 95.0   # Avoid cold (0% = no miners)

    return util * 80  # Score 0-80 based on utilization

_build_dynamic_chain() — Returns sorted list:

# Score and sort all models in family
scored.sort(key=lambda x: x[0])  # Lowest first
chain = [model for _, model, _, _ in scored]

# Append static fallbacks
chain.extend(["text-kimi", "text-qwen3", "text-qwen3-large"])
return chain

pre_call() — Injects chain into request:

chain = await _build_dynamic_chain(family, util_cache)
request["_dynamic_fallback_chain"] = chain  # Key injection
request["model"] = chain[0]  # Route to best model

3 router.py — Use the Chain

# Line 758-766
dynamic_chain = kwargs.pop("_dynamic_fallback_chain", None)
if dynamic_chain:
    chain = dynamic_chain  # Use utilization-sorted chain
else:
    chain = self._fallback_chain(group_name)  # Fall back to static config

# Then iterate through chain until success
for model in chain:
    try:
        return await self._call_provider(model, ...)
    except RateLimitError:
        continue  # Try next in chain

Why This Fixes 429s

Before After
Chimera-TEE discovered dynamically Same
Chimera-TEE has no fallback chain in static config Chain built dynamically with 8 models
429 → returned to client 429 → try V3.1-TEE → try R1-0528 → ... → text-qwen3-large

Key Design Decisions

Decision Why
5-minute cache Balance freshness vs API overhead
Score 0-100 Simple sort, lower = better
25% rate-limit threshold Avoid models actively rejecting requests
Static fallbacks at end Kimi/Qwen3 don't have utilization data, but are reliable last resorts
Inject via request body Middleware can't call router directly; body is the transport
